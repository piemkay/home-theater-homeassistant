1a

Library as a place, not a panel

WHAT BREAKS TODAY
Tapping Filme, Serien or Erkunden does not navigate — it grows a second screen underneath the one you are on. The room controls stay above it, so browsing 753 titles happens in the last third of a long scroll, and every return trip means scrolling back up past the light scenes.
FOUR CONCRETE ISSUES
1
Two navigation models in one view. The four source cards behave like a menu, but the result is rendered inline, so there is no screen to go back from — hence a ‹ Zurück link floating in the middle of the page instead of in a bar.
2
Controls compete with content. Light scenes are a 5-second task; picking a film is a 60-second task. The short task permanently occupies the top of the long one.
3
Tabs shift and change between states — Filme / Serien in one, Filme / Serien / Demos in the other, at different scroll offsets. The segment you just tapped moves under your thumb.
4
Search, filter, sort and the grid all scroll away. With 753 titles the toolbar is the one thing that must stay reachable.
THE PROPOSAL
Home stays what it is good at: the state of the room. It keeps the four sources, the light scenes, and one Weitersehen shelf — the only content you actually resume from home.
Browsing becomes its own view. The Home Assistant header (hamburger, Kino, ⋮) stays untouched on every view; directly beneath it the library view gets a sub-bar with ‹ Zurück and the view title. The tab set is fixed at three, and search + filter + sort stick under the tabs while only the grid scrolls. Same cards, same radii, same orange.
SIDE EFFECTS
Home shortens by roughly one screen height. Streaming, Musik and Steam get the same push pattern for free. The grid gains ~340px of vertical room, so the first row is visible without scrolling.
